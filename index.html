Foundation · Module 01

Optimization Problem
Framing

Định nghĩa bài toán như một kỹ sư sản xuất: objective function rõ ràng, constraint cứng, trade-off được định lượng. Không còn "hiển thị quảng cáo phù hợp" — mà là maximize revenue under constraints.

Objective Function — Công thức chính thức
Cái hệ thống cần maximize mỗi impression
Core Math
# PRIMARY OBJECTIVE — maximize Expected Revenue per Impression (eRPI) eRPI(u, c, t) = argmax Σ_{a ∈ CandidateSet} score(u, a, c, t) where: score(u, a, c, t) = P(interaction | u, a, c, t) × bid(a) × relevance_weight(u, a) × business_priority(a) - diversity_penalty(a, selected_ads) - frequency_penalty(u, a, t) Biến: u = user feature vector # identity + behavior a = ad feature vector # metadata + bid c = context vector # GPS, POI, weather, event t = time vector # hour, day_type, trip_stage P(interaction | u,a,c,t) # ML model output — Phase 2 # Rule-based proxy — Phase 1 bid(a) # CPM submitted by advertiser relevance_weight # guardrail: prevent pure pay-to-win business_priority # GSM internal weighting (e.g. strategic partners) diversity_penalty # reduce same-brand repeats in one trip frequency_penalty # freq_shown(u,a, 7d) / freq_cap(a)
Constraint cứng (Hard)
Must satisfy
C1
Frequency Cap
impressions(u, a, 7d) ≤ freq_cap(a). Vi phạm → loại khỏi candidate set ngay.
C2
Budget Cap
spend(a, campaign) ≤ budget(a). Hết budget → pause ngay, không serve thêm.
C3
Targeting Match
district ∈ target_districts AND hour ∈ target_hours. Hard filter, không bypass.
C4
Brand Safety
Không serve 2 direct competitors trong cùng 1 trip. Lookup brand conflict matrix.
Constraint mềm (Soft)
Penalized
S1
Diversity
Không quá 2 ads cùng category trong 1 trip. Penalty tăng dần theo số lần lặp.
S2
Relevance Floor
relevance_score(u,a) ≥ 0.2 để serve. Ads không liên quan dù bid cao cũng bị penalty.
S3
Fill Rate
Phải có ≥1 ad cho mỗi impression slot. Nếu không đủ candidate → fallback chain.
S4
Pacing
Budget phân bổ đều theo ngày, không burn hết trong vài giờ đầu.
Trade-off tam giác
Fundamental
△
Không thể tối ưu cả 3 cùng lúcMỗi quyết định thiết kế là một sự đánh đổi có chủ ý.
↑ Relevance
User experience tốt hơn → CTR cao hơn → nhưng fill rate giảm, revenue/slot giảm ngắn hạn
↑ Revenue
Ưu tiên highest bidder → fill rate cao → nhưng irrelevant ads → user experience xấu dần
↑ Fill Rate
Luôn có ad → serve default/brand-awareness → nhưng dilutes personalization signal
→
Khuyến nghị Phase 1Ưu tiên fill rate (70%) + relevance (20%) + revenue (10%). Đảo tỉ lệ khi đủ data.
Scoring formula — Phase 1 (rule-based)
Triển khai ngay
score_p1(u, a, c, t) = 0.40 × user_match(u, a) + 0.35 × context_match(c, a) + 0.15 × bid_norm(a) + 0.10 × stage_fit(t.trip_stage, a.preferred_stage) - penalty_freq × max(0, freq_shown(u,a,7d) - freq_cap(a)/2) ── user_match ──────────────────────────────── user_match = cosine_sim(u.interest_vec, a.category_vec) × age_compat(u.age_bucket, a.target_age) × gender_compat(u.gender, a.target_gender) ── context_match ────────────────────────────── context_match = poi_match(c.nearest_poi, a.target_poi) # 0/0.5/1 + time_match(t.hour, a.target_hours) # 0/0.5/1 + district_match(c.district, a.districts) # 0/1 ── bid_norm ──────────────────────────────────── bid_norm = log(bid_cpm) / log(max_bid_in_pool) # [0,1]
Scoring formula — Phase 2 (ML-based)
Phase 2
score_p2(u, a, c, t) = P̂(click | u,a,c,t) × bid(a) × quality_factor(a) ── Model output ─────────────────────────────── P̂(click) = LightGBM_ranker.predict( feature_vector = [ user_features, # 15 dims ad_features, # 12 dims context_features, # 10 dims cross_features, # user×ad, ctx×ad: 8 dims historical_ctr(a) # ad-level smoothed CTR ] ) ── quality_factor ───────────────────────────── quality_factor = 0.7 + 0.3 × historical_ctr(a) / benchmark_ctr # penalize ads with proven poor performance # even if they bid high ── Production note ──────────────────────────── # Kết hợp P̂×bid (eCPM auction) thay vì pure bid # Điều này tạo incentive cho advertiser làm creatives tốt

Data Layer · Module 04

Feature
Engineering

Các kỹ thuật biến đổi feature từ raw data sang representation có ích cho model. Tập trung vào Interest Vector, POI Embedding, và temporal encoding — những thứ tạo ra lift thực sự.

Interest Vector — từ trips đến sở thích
K-dim probability vector, cập nhật daily
Core Feature

Interest vector là xác suất user quan tâm đến từng danh mục quảng cáo. Được suy ra từ lịch sử chuyến đi bằng cách map destination POI → ad category → normalize.

# Bước 1: Map mỗi trip đến POI category def build_interest_vector(trips: List[Trip]) -> np.ndarray: # Category weights (prior từ business knowledge) prior = {'F&B': 0.25, 'Travel': 0.1, 'Finance': 0.15, 'Retail': 0.2, 'Entertainment': 0.15, 'Health': 0.05, 'Education': 0.05, 'Automotive': 0.05} counts = defaultdict(int) for trip in trips: poi_type = lookup_poi_category(trip.dropoff_lat, trip.dropoff_lng) ad_cat = POI_TO_AD_CATEGORY[poi_type] counts[ad_cat] += 1 # Bayesian smoothing: blend observed với prior alpha = 10 # equivalent to 10 "prior" observations n = len(trips) smoothed = {} for cat in prior: observed = counts.get(cat, 0) / max(n, 1) smoothed[cat] = (counts.get(cat, 0) + alpha * prior[cat]) / (n + alpha) # Normalize to probability simplex vec = np.array(list(smoothed.values())) return vec / vec.sum()
★
Tại sao Bayesian smoothing?User mới có ít trips → observed ratio không ổn định. Shrinkage về prior giúp cold-start users có vector hợp lý ngay từ trip thứ 1.
POI Embedding — dense representation
Word2Vec-style, train trên trip sequences
Embedding

Thay vì one-hot encode POI type (sparse, 50+ types), train Word2Vec trên chuỗi POI mà users ghé thăm. POIs thường đi cùng nhau sẽ có embedding gần nhau.

# Train POI2Vec trên trip sequences # "Sentences" = chuỗi POI types của mỗi user theo thời gian sentences = [] for user_id in users: poi_seq = [trip.dropoff_poi_type for trip in get_trips(user_id, '90d')] sentences.append(poi_seq) # Word2Vec với skip-gram from gensim.models import Word2Vec model = Word2Vec( sentences, vector_size=16, # 16-dim embedding window=3, # 3 POIs trước/sau min_count=5, # ignore rare POI types sg=1 # skip-gram ) # User POI embedding = mean of recent POIs def user_poi_embedding(user_trips, model, k=20): recent_pois = [t.dropoff_poi_type for t in user_trips[-k:]] vecs = [model.wv[p] for p in recent_pois if p in model.wv] return np.mean(vecs, axis=0) if vecs else np.zeros(16)
Temporal encoding — cyclical features
Tránh model hiểu sai 23h và 0h là xa nhau
# WRONG: dùng raw hour (0–23) → model nghĩ 23 và 0 rất khác nhau # CORRECT: cyclical encoding dùng sin/cos hour = 23 hour_sin = np.sin(2 * np.pi * hour / 24) # -0.259 hour_cos = np.cos(2 * np.pi * hour / 24) # +0.966 hour = 0 hour_sin = np.sin(2 * np.pi * 0 / 24) # 0.0 hour_cos = np.cos(2 * np.pi * 0 / 24) # 1.0 # Khoảng cách Euclidean của 23h và 0h bây giờ ≈ 0.26 ✓ # Tương tự cho day_of_week (chu kỳ 7) dow_sin = np.sin(2 * np.pi * day_of_week / 7) dow_cos = np.cos(2 * np.pi * day_of_week / 7)

Recommendation · Module 05

Candidate
Generation

Từ toàn bộ ad pool (có thể hàng nghìn ads), lọc xuống còn 20–50 candidates đủ điều kiện trong <30ms. Bước này tập trung vào recall (không bỏ sót good ads), không phải precision.

Two-stage retrieval pipeline
Hard filter → Soft pre-rank → Top-50 → Full ranking
①
Hard filter — loại ngay, không score
budget_remaining > 0 AND freq_shown(u,a,7d) < freq_cap(a) AND district ∈ target_districts AND ad.status = ACTIVE. Kết quả: từ N ads → ~200 ads.
# Prebuilt inverted index: district → [ad_ids] # + Bloom filter cho freq cap check (O(1)) candidates = district_index[ctx.district] candidates = [a for a in candidates if not freq_bloom.check(user_id, a.id) and budget_cache[a.campaign_id] > 0]
②
Soft pre-rank — nhanh, approximate
Dùng category match + time match (pre-computed lookup table) để sort 200 candidates. Lấy top-50. Không cần full scoring.
# Pre-rank score (approximate, no ML) pre_score = ( category_compat[user.cluster_id][ad.category] # lookup table + time_compat[hour_bucket][ad.target_hours] # lookup table + poi_compat[ctx.nearest_poi][ad.target_poi] # lookup table ) top50 = sorted(candidates, key=lambda a: pre_score(a))[-50:]
③
Full ranking — chỉ trên top-50
Apply full scoring formula (Phase 1) hoặc ML model inference (Phase 2) trên 50 candidates. Output: top-5 ads cho toàn bộ chuyến đi.

Cold Start · Module 08

3-Case Cold
Start Strategy

Ba tình huống cold start hoàn toàn khác nhau và cần chiến lược riêng: new user (không biết sở thích), new ad (không biết hiệu quả), new location (không có historical data).

Case 1 — New User
Người dùng lần đầu dùng XanhSM
Most Common
Trip 1–4
Demographic proxy
Dùng age_bucket + gender từ đăng ký. Interest vector = prior distribution. Kết hợp full context matching.
Trip 5–9
Pattern emergence
Bắt đầu thấy pattern (peak hour, zones). Interest vector bắt đầu hội tụ. Bayesian update mỗi trip.
Trip 10+

A/B Testing framework
Standard randomized experiment — dùng thường xuyên nhất
Most Used
1
Randomization unit = user_token
Hash(user_token + experiment_id) % 100 → assign group. Đảm bảo same user luôn vào cùng group.
2
Holdout group — 10% traffic
Group thấy PSA thay vì commercial ads. Measure: store_visit_rate(exposed) - store_visit_rate(holdout) = true lift.
3
Sample size calculation trước
MDE = 0.5% (minimum detectable effect), α=0.05, power=0.8. Tính sample size cần để kết quả có ý nghĩa thống kê.
from scipy.stats import norm mde, alpha, power = 0.005, 0.05, 0.80 z_alpha = norm.ppf(1 - alpha/2) z_power = norm.ppf(power) baseline_cvr = 0.028 # store visit rate n = 2 * (z_alpha + z_power)**2 * baseline_cvr * (1-baseline_cvr) / mde**2 # → n ≈ 8,450 users per group
4
Sequential testing
Dùng mSPRT thay vì fixed-horizon để có thể early stop nếu effect rõ ràng. Tránh peek-and-stop.
Geo Experiment
Khi không thể randomize by user — dùng geographic units
Geo Split
ℹ
Khi nào dùng?Advertiser yêu cầu: "chứng minh campaign này bring customers đến 50 stores của chúng tôi." Không thể randomize bằng user (advertiser không chấp nhận holdout). → Randomize bằng geographic unit.
1
Pair matching districts
Tìm cặp districts tương đồng (population, traffic volume, baseline store visit rate). Assign một cái là treatment, một cái là control.
2
Run campaign chỉ trong treatment districts
Control districts không nhận bất kỳ ads nào của brand này. Collect store visit data từ cả hai.
3
DiD (Difference-in-Differences)
Lift = (Δ store visit treatment) - (Δ store visit control). Controls for seasonal trends và external effects.
# DiD estimator lift = (SV_treat_post - SV_treat_pre) - (SV_ctrl_post - SV_ctrl_pre) # Robust to: seasonality, economic changes, competitor activity
Uplift Modeling
Identify users who respond to ads — skip "always buyers"
Advanced
⚠
Vấn đề với standard targetingStandard model: target users có P(buy) cao. Nhưng "always buyers" sẽ mua dù không xem ads → waste budget. Uplift model tìm users có P(buy | ad) - P(buy | no ad) cao nhất.
# Uplift = CATE (Conditional Average Treatment Effect) # tau(x) = E[Y(1) - Y(0) | X=x] # S-Learner approach (simple, good starting point) from causalml.inference.meta import BaseSLearner from lightgbm import LGBMRegressor uplift_model = BaseSLearner(learner=LGBMRegressor()) uplift_model.fit(X=features, treatment=treatment_flag, y=outcome) tau = uplift_model.predict(X=new_users) # Segment by uplift score # "Persuadables" (high tau): target these — they respond to ads # "Sure things" (high base, low tau): skip to save budget # "Lost causes" (low base, low tau): skip # "Sleeping dogs" (low base, negative tau): NEVER target (ads hurt)
→
Triển khai thực tếPhase 3 (sau 6 tháng data). Cần paired exposure/control data từ A/B test trước. Expected: 15–25% budget savings với cùng hoặc tốt hơn ROI.
